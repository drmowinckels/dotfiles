## What counts as a failure

Report these as **Important**:

- Wrong results returned silently — a plot, table, or transformation that looks right and isn't
- A change to an exported function's signature, defaults, or return type without a deprecation path
- S3/S4 method dispatch that breaks for a class the package already supports
- Anything that makes `R CMD check` fail, or adds a NOTE on CRAN
- A new branch or changed behaviour with no test exercising it
- Non-UTF8, locale-dependent, or platform-dependent behaviour in user-facing output
- A new hard dependency in `Imports` that isn't justified in the PR description
- [Project-specific: e.g. atlas data whose region count or palette no longer matches its source]

## What is not a failure

Do not report:

- Style, naming, or formatting — `air` and `lintr` own those and run in CI
- Missing roxygen on internal (non-exported) helpers
- Hypotheticals without a concrete input that triggers them
- Performance opinions without a measured cost on realistic data
- Pre-existing issues outside the diff, unless the diff makes them materially worse — tag
  those `Pre-existing` and keep them to one line each

## Evidence standard

Every finding cites `file:line` and a concrete failure scenario: specific inputs or state →
specific wrong output. A claim you cannot anchor to a line is not a finding.

## Nit budget

At most **3** nits per review. If there are more, the three that matter most, and drop the rest.
